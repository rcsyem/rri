# RRI — استخبارات الاستطلاع

**أداة سطر أوامر (CLI) متخصصة في الاستطلاع الأمني، تساعد على اكتشاف تقنيات تطبيقات الويب، ومراجع واجهات API، وإعدادات ترويسات HTTP الأمنية، والمؤشرات الأمنية المحتملة.**

RRI أداة محلية للاستطلاع الأمني، صُممت لمساعدة الباحثين الأمنيين ومختبري الاختراق المصرح لهم على فهم الخصائص التي يمكن ملاحظتها من الخارج في تطبيقات الويب.

تجمع الأداة عدة وحدات للاستطلاع والتحليل، وتربط النتائج باستخدام محرك ترابط (Correlation Engine)، ثم تنشئ تقارير بصيغتي HTML وJSON.

> **حالة المشروع:** مرحلة التطوير المبكرة — الإصدار 0.1.0.

## الميزات

### 1. التعرف على التقنيات (Technology Fingerprinting)

تتعرف الأداة على التقنيات المستخدمة في تطبيق الويب اعتماداً على مؤشرات يمكن ملاحظتها، مثل:

- ترويسات استجابة HTTP.
- ملفات تعريف الارتباط (Cookies).
- بيانات HTML الوصفية (Meta Tags).
- محتوى صفحات HTML.
- مراجع ملفات JavaScript وCSS.
- مؤشرات أطر العمل والمكتبات البرمجية.

تعتمد النتائج على المؤشرات المكتشفة، ولا تعني بالضرورة تأكيد استخدام تقنية معينة.

### 2. اكتشاف واجهات API (API Discovery)

تكتشف الأداة المراجع والمسارات المحتملة لواجهات API من خلال:

- محتوى HTML.
- أكواد JavaScript المضمنة داخل الصفحة.
- ملفات JavaScript الموجودة ضمن النطاق المصرح به.
- الأنماط الشائعة لواجهات REST وGraphQL.
- مراجع وثائق OpenAPI وSwagger.

**ملاحظة مهمة:** اكتشاف مسار API لا يعني أن الأداة تختبره أو تتحقق من إمكانية الوصول إليه. لا ترسل RRI طلبات تلقائية إلى واجهات API المكتشفة.

### 3. تحليل ترويسات HTTP (HTTP Headers Analysis)

تفحص الأداة وجود بعض ترويسات الأمان المهمة، ومنها:

- Strict-Transport-Security (HSTS).
- Content-Security-Policy (CSP).
- X-Frame-Options.
- X-Content-Type-Options.
- Referrer-Policy.
- Permissions-Policy.
- ترويسات العزل عبر الأصول (Cross-Origin Isolation Headers).

كما تفحص بعض خصائص الأمان المرتبطة بملفات تعريف الارتباط (Cookie Security Attributes)، مثل:

- Secure.
- HttpOnly.
- SameSite.

تساعد هذه الفحوصات على اكتشاف الإعدادات التي قد تحتاج إلى مراجعة، لكنها لا تمثل تدقيقاً كاملاً لجميع سياسات الأمان.

### 4. الفحوصات الأمنية السلبية (Passive Security Checks)

تبحث الأداة داخل الصفحة التي جرى جلبها عن مؤشرات أمنية محتملة، مثل:

- مراجع مسارات الإدارة.
- مراجع الملفات الحساسة أو ملفات النسخ الاحتياطية.
- مراجع Source Maps.
- رسائل الأخطاء والتصحيح (Debug).
- أنماط تشير إلى إعدادات أو مفاتيح سرية محتملة.
- مؤشرات عرض محتويات المجلدات (Directory Listing).
- مراجع لمسارات داخلية وعناوين خاصة.

هذه النتائج مؤشرات أولية تحتاج إلى تحقق يدوي، ولا تعني أن ثغرة أمنية مؤكدة موجودة.

### 5. محرك ترابط النتائج (Correlation Engine)

يربط المحرك الأدلة التي تكتشفها الوحدات المختلفة، ويساعد الباحث على ملاحظة العلاقات بين:

- مراجع واجهات API.
- مؤشرات التقنيات.
- نتائج تحليل ترويسات HTTP.
- نتائج الفحوصات الأمنية السلبية.

يعتمد الترابط على تداخل الأدلة بين النتائج. ولا يثبت وحده وجود ثغرة أو إمكانية استغلالها.

### 6. إنشاء التقارير (Reporting)

يمكن إنشاء التقارير بالصيغ التالية:

- HTML.
- JSON.
- الصيغتان معاً.

تتضمن التقارير نتائج الوحدات المختلفة، وملخصات درجات الخطورة، والعلاقات المكتشفة بين الأدلة.

## متطلبات التشغيل

تحتاج الأداة إلى:

- Python 3.11 أو أحدث.
- pip.
- مكتبة aiohttp بإصدار 3.12 أو أحدث، وأقل من الإصدار 4.
- نظام تشغيل يدعم Python وaiohttp.

تم تطوير RRI واختبارها في بيئة Kali Linux.

## التثبيت

نوصي باستخدام [pipx](https://pipx.pypa.io/) لتثبيت RRI؛ فهو ينشئ بيئة
Python مستقلة للأداة، ويجعل الأمر `rri` متاحاً دون الحاجة إلى تفعيل
بيئة افتراضية يدوياً.

### 1. تثبيت pipx

على Kali Linux والأنظمة المبنية على Debian:

    sudo apt update
    sudo apt install pipx
    pipx ensurepath

أعد تشغيل الطرفية إذا لزم الأمر.

### 2. تنزيل RRI وتثبيتها

استنسخ المستودع الرسمي:

    git clone https://github.com/rcsyem/rri.git
    cd rri

ثم ثبّت الأداة:

    pipx install .

### 3. التحقق من التثبيت

    rri --version
    rri --help

يفترض أن يصبح الأمر `rri` متاحاً من أي مجلد.

### طريقة بديلة: البيئة الافتراضية

يمكن للمطورين الذين يفضلون استخدام بيئة افتراضية تقليدية تنفيذ:

    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install -e .

ثم التحقق:

    rri --version

## الاستخدام

تبدأ عملية الاستطلاع بإدخال عنوان الهدف صراحةً باستخدام الخيار `-u`.

مثال:

    rri -u https://example.com

يجب أن يكون الهدف ضمن الأنظمة التي تملكها أو لديك تصريح صريح بفحصها.

### خيارات سطر الأوامر (CLI Options)

| الخيار | الوظيفة |
|---|---|
| `-u`, `--url` | عنوان الهدف، وهو خيار مطلوب. |
| `-f`, `--format` | صيغة التقرير: `html` أو `json` أو `both`. الافتراضي `html`. |
| `-o`, `--output` | تحديد مسار مخصص لحفظ التقرير. |
| `-V`, `--version` | عرض إصدار الأداة. |
| `--no-color` | تعطيل ألوان الطرفية. |
| `-h`, `--help` | عرض تعليمات الاستخدام. |

### إنشاء تقرير HTML

    rri -u https://example.com -f html

### إنشاء تقرير JSON

    rri -u https://example.com -f json

### إنشاء التقريرين معاً

    rri -u https://example.com -f both

### تحديد مسار حفظ التقرير

    rri -u https://example.com -f both -o reports/example

عند اختيار `both`، تنشئ الأداة ملفين منفصلين بامتدادي `.html` و`.json` اعتماداً على مسار الإخراج المحدد.

## النطاق والأمان

تستخدم RRI نموذجاً صارماً للتحكم في النطاق المصرح به (Scope).

### النطاق الافتراضي

عند إدخال هدف باستخدام `-u`، تستخرج الأداة النطاق الافتراضي المصرح به من عنوان الهدف.

السلوك الافتراضي:

- يُسمح باسم المضيف (Hostname) المحدد فقط.
- لا يُسمح بالنطاقات الفرعية (Subdomains) تلقائياً.
- يُسمح بجميع المسارات على اسم المضيف المصرح به.
- تُحظر العناوين الواقعة خارج النطاق المصرح به.

على سبيل المثال، إدخال:

    rri -u https://example.com

لا يمنح تصريحاً تلقائياً بفحص:

    https://api.example.com

لأن النطاق الفرعي يحتاج إلى تصريح صريح.

### حماية الاتصالات (Network Safety)

تتضمن طبقة الاتصالات إجراءات حماية، منها:

- التحقق من نتائج DNS وعناوين IP العامة.
- رفض عناوين IP الخاصة وغير العامة.
- التحقق من النطاق عند اتباع التحويلات (Redirects).
- التحقق من صحة عناوين URL وأسماء المضيفين.
- تحديد الحد الأقصى لحجم الاستجابة.
- وضع حدود على ترويسات HTTP.
- تحديد مهلة زمنية للطلبات.

### الاستطلاع السلبي (Passive Discovery)

لا ترسل RRI طلبات تلقائية إلى:

- واجهات API المكتشفة.
- المسارات الحساسة المشار إليها داخل الصفحة.
- مسارات الإدارة التي تظهر كمراجع داخل المحتوى.

يمكن جلب ملفات JavaScript فقط عندما تكون ضمن النطاق المصرح به، مع الالتزام بالحد المحدد لعدد الملفات.

**تنبيه:** استخدم الأداة فقط على الأنظمة التي تملكها أو لديك تصريح صريح باختبارها. تقع مسؤولية الالتزام بالقوانين وشروط التصريح على عاتق المستخدم.

راجع [دليل النطاق والأمان](docs/SCOPE-AND-SAFETY.md) لمزيد من التفاصيل.

## بنية المشروع

تنقسم RRI إلى طبقة أساسية (Core) ووحدات متخصصة للاستطلاع (Modules).

    rri/
    ├── core/
    │   ├── scope.py
    │   ├── network_safety.py
    │   ├── dns_resolver.py
    │   ├── redirect_guard.py
    │   ├── http_engine.py
    │   ├── correlation_engine.py
    │   └── reporting.py
    │
    ├── modules/
    │   ├── technology.py
    │   ├── api_discovery.py
    │   ├── headers_analysis.py
    │   └── security_checks.py
    │
    ├── tests/
    ├── reports/
    ├── config/
    ├── main.py
    ├── pyproject.toml
    └── requirements.txt

### الطبقة الأساسية (Core)

مسؤولة عن الوظائف المشتركة، مثل:

- إدارة النطاق المصرح به.
- التحقق من سلامة الاتصالات.
- إدارة استعلامات DNS.
- التحقق من التحويلات.
- تنفيذ طلبات HTTP.
- ربط النتائج.
- إنشاء التقارير.

### وحدات الاستطلاع (Modules)

تنفذ كل وحدة مهمة مستقلة، وتعيد نتائج منظمة يمكن استخدامها في التحليل والتقارير.

راجع [شرح البنية المعمارية](docs/ARCHITECTURE.md) للتفاصيل.

- التعامل مع التحويلات (Redirects).
- التعرف على التقنيات.
- اكتشاف واجهات API.
- تحليل ترويسات HTTP.
- الفحوصات الأمنية السلبية.
- محرك ترابط النتائج.
- إنشاء التقارير.

    .venv/bin/python -m unittest discover -s tests -v

تُستخدم الاختبارات للتحقق من سلوك المكونات دون الحاجة إلى إجراء استطلاع فعلي على موقع خارجي.

## إخلاء المسؤولية

RRI أداة للاستطلاع والتحليل الأمني. تعتمد نتائجها على الأدلة الظاهرة وأساليب الكشف القائمة على الأنماط والمؤشرات.

ظهور نتيجة لا يعني بالضرورة وجود ثغرة أمنية، كما أن عدم ظهور نتائج لا يضمن أن النظام آمن.

يجب التحقق من النتائج يدوياً، والحصول على تصريح مناسب قبل اختبار أي نظام.

RRI ليست بديلاً عن المراجعة الأمنية المتخصصة أو الاختبارات الأمنية الشاملة.
